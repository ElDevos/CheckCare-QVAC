# Architecture

## Components

### `apps/web` — Next.js frontend

Spanish-first UI. Talks to `apps/edge` only over `http://127.0.0.1:4111` (or `localhost:4111`),
never imports `@qvac/sdk`, and never touches the SQLite database directly. CORS on the edge server
is restricted to `http://localhost:3000` and `http://127.0.0.1:3000` — no wildcard origin.

### `apps/edge` — Edge Runtime

Node.js + TypeScript, the only process that imports `@qvac/sdk`.

- `src/qvac/qvac-client.ts` — the single import boundary for `@qvac/sdk`. Every other module goes
  through this file, which also resolves the model paths.
- `src/qvac/model-manager.ts` — owns MedPsy's lifecycle (`NOT_INSTALLED → LOADING → READY → BUSY →
  ERROR / UNLOADING`), loads once, serializes concurrent completion requests.
- `src/qvac/embeddings.ts` — owns the embedding model (`EmbeddingGemma-300M`) lifecycle,
  independent of MedPsy so both can be resident simultaneously.
- `src/qvac/medpsy.ts` — builds the controlled system/user prompt, calls `completion()` with a
  strict JSON schema (`responseFormat: 'json_schema'`), parses and validates the shape of the
  response.
- `src/qvac/rag.ts` — chunks/ingests/searches the local knowledge base via QVAC's built-in
  `ragIngest`/`ragSearch`, with a tag-based source-attribution scheme (see below).
- `src/qvac/benchmark.ts` — real, measured performance benchmark (`npm run benchmark`).
- `src/safety/safety-engine.ts` — deterministic risk evaluation. No LLM calls. Pure function.
- `src/assessment/question-engine.ts` — deterministic adaptive-question selection from the
  symptom catalog (`packages/safety-rules`), no LLM.
- `src/assessment/assessment-engine.ts` — orchestrates Safety Engine → RAG → MedPsy → Validator →
  `AssessmentResult`, with a deterministic fallback template if MedPsy's output fails validation
  twice.
- `src/assessment/response-validator.ts` — pattern-based rejection of diagnosis claims,
  prescriptions, false certainty, and risk-level contradictions.
- `src/db/db.ts` — SQLite (`better-sqlite3`), local-only.
- `src/api/` — Express routes (see README's endpoint list), input-validated with `zod`.

### `packages/shared-types`

The `RiskLevel`, `AssessmentResult`, `SafetyRule`, and related types shared by the edge runtime
and (via re-export) the web app. `RiskLevel` deliberately excludes any "healthy/safe/nothing
wrong" value.

### `packages/safety-rules`

The versioned, source-cited safety rule set (`RULES_VERSION`), the adaptive-question catalog
(`QUESTIONS`), and the canonical symptom vocabulary (`SYMPTOMS`) — the shared vocabulary between
the deterministic question engine and the deterministic safety engine.

### `packages/ui`

Shared design tokens (risk-level color mapping) so the color for e.g. `EMERGENCY` cannot drift
between components.

### `knowledge/`

`sources/*.json` — one file per real, cited source (currently NHS.uk pages, retrieved
2026-09-10). `manifest.json` — the id/title/source/url/topic index used to resolve citations.
`processed/chunks.json` — generated by `scripts/ingest-knowledge.ts`, not hand-written.

### `evaluation/`

`cases/*.json` — hand-written test cases with an NHS-sourced `rationale` and `expectedRisk`.
`reports/` — generated by `npm run evaluate` and `npm run benchmark`; never hand-edited.

## RAG source-attribution scheme

QVAC's built-in `ragIngest`/`ragSearch` (the documented "prototype" vector store) round-trips only
`{id, content, score}` per hit — it does not pass arbitrary per-document metadata through search
(confirmed against `@qvac/rag`'s `SearchResult` type, which has no `metadata` field, unlike the
lower-level `EmbeddedDoc`). To guarantee every citation shown to a user traces back to a real,
versioned knowledge-base entry, each ingested chunk is tagged with a machine-parseable
`[[sourceId#chunkId]]` prefix. After retrieval, `apps/edge/src/qvac/rag.ts` strips that tag and
resolves `sourceId` against `knowledge/manifest.json` — never against anything the model produced.
A chunk whose tag doesn't resolve is dropped, not shown.

## Data flow (one assessment)

```text
User symptoms + answers
        │
        ▼
Safety Engine (deterministic) ──────────────► riskLevel (floor, never lowered downstream)
        │
        ▼
RAG retrieveContext(query) ─────────────────► sources[] (from manifest.json only)
        │
        ▼
MedPsy completion() (JSON schema output) ───► { summary, warningSigns, recommendedNextSteps,
        │                                        questionsToMonitor, uncertainty }
        │                                       (NO riskLevel field — structurally cannot
        │                                        override the Safety Engine)
        ▼
Response Validator ──────────────────────────► pass → use MedPsy output
        │                                       fail (after 1 retry) → deterministic fallback
        ▼
AssessmentResult { riskLevel: <from Safety Engine>, ...validated MedPsy or fallback text, sources }
        │
        ▼
SQLite (local) + returned to web UI
```

## Process boundary note

QVAC's local RAG/registry storage (RocksDB/Hypercore-backed, under `~/.qvac`) takes an exclusive
file lock. Only one Node process should hold it at a time — running `npm run dev` (which loads
MedPsy + the embedding model) and `npm run evaluate` or `npm run ingest-knowledge` concurrently
will fail with `File descriptor could not be locked`. Stop the dev server before running the
evaluation or ingestion scripts, or vice versa.
